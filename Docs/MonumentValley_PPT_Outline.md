# 《纪念碑谷》风格 Unity 解谜游戏 PPT 大纲

## 第 1 页：封面

- 标题：《纪念碑谷》风格 Unity 解谜游戏
- 副标题：从 Python 图形学原型到 Unity 可玩原型
- 信息：课程项目汇报、姓名、学号、日期

备注讲稿：大家好，我汇报的项目是一款《纪念碑谷》风格的 Unity 解谜游戏。项目经历了 Python 原型和 Unity 开发两个阶段，重点实现视觉错觉形成的非欧连通玩法。

## 第 2 页：项目背景与目标

- 参考《纪念碑谷》的等距视角和视觉错觉
- 核心体验：旋转建筑，让 3D 中断开的路在屏幕上连通
- 第一阶段：用 Python 验证投影、旋转和连通算法
- 第二阶段：用 Unity 完成可玩流程和 Windows 打包
- 当前定位：课程原型，不是完整商业游戏

备注讲稿：项目目标不是简单复刻，而是验证“看起来连通就能走过去”这套玩法。第一阶段解决图形学可行性，第二阶段重点把它整理成完整的游戏流程。

## 第 3 页：两阶段技术路线

- Python：Python 3、PyOpenGL、pygame、sqlite3
- Unity：Unity 2019.2.3f1、C#、DOTween、ProBuilder、uGUI
- 第一阶段自研投影、拾取、动画和连通逻辑
- 第二阶段复用 Unity 的相机、碰撞、动画和打包能力
- 核心算法从 Python 思路迁移到 Unity 节点图

备注讲稿：前期我们用 PyOpenGL 自己搭渲染和拾取，调试成本很高。后来转向 Unity，把精力集中到玩法、关卡和表现上，Python 阶段的投影和连通思路仍然保留下来。

## 第 4 页：核心玩法，非欧连通

- 相机采用等距正交视角
- 节点可站立点投影到屏幕坐标
- 屏幕距离足够近，但世界坐标仍有间隔
- 两个条件同时满足时，开放移动连接
- 不修改场景几何，只动态切换图连接

备注讲稿：这页是项目最核心的机制。玩家看到两条路接上了，但 3D 空间里它们并没有真正贴合。系统根据屏幕投影和世界距离共同判断，只有视觉上相接时才允许通行。

## 第 5 页：Unity 系统架构

- `Walkable` 保存相邻路径和节点属性
- `WalkGraph` 使用 BFS 计算最短路径
- `PlayerController` 管理移动状态和角色朝向
- `PivotController` 与 `CameraController` 处理 90 度旋转
- `GameManager` 管理条件连边和按钮机关

备注讲稿：整体架构围绕可行走节点图展开。场景负责放方块，脚本负责判断哪些节点当前可通行。这样可以把视觉表现和连通规则分开维护。

## 第 6 页：角色、相机与旋转

- 鼠标点击目标方块，角色自动寻路
- 状态机区分空闲、移动和锁定
- 移动中拒绝重复点击，避免状态冲突
- 楼梯根据高度差调整动画表现
- 枢轴和相机都采用离散步进，避免角度漂移

备注讲稿：角色移动主要依赖 BFS 寻路。相机和枢轴都按 90 度旋转，而不是持续插值，这样条件判断更稳定，也方便之后重新计算连通关系。

## 第 7 页：条件连通与机关

- 支持物体角度条件
- 支持相机四分之一转向条件
- 条件满足后开放指定路径
- 按钮可以让枢轴旋转并触发机关
- 第二关加入视觉对齐开放连接的规则

备注讲稿：关卡中的门不是靠碰撞开关，而是靠节点图动态开关。玩家旋转枢轴或相机后，系统重新检查条件，再决定哪些边可以走。

## 第 8 页：关卡流程

- 第一关：`SampleScene`
- 第二关：`Scene 2`
- 完成第一关后解锁第二关
- 存档记录最高解锁关卡和最后关卡
- 支持关卡选择、重试、暂停和退出

备注讲稿：目前游戏有两个关卡。完成第一关后会解锁第二关，进度通过 PlayerPrefs 保存。第二次启动时，玩家可以直接选择已经解锁的关卡。

## 第 9 页：UI 与视觉表现

- UI 使用深紫背景和紫粉按钮
- HUD 精简为左上角，减少画面遮挡
- 暂停、完成和关卡选择面板统一风格
- 第二关加入柔和光照、阴影和渐变背景
- 增加环境颗粒与淡入淡出过渡

备注讲稿：UI 经过几轮调整，最终减少了顶部元素，避免遮挡解谜画面。第二关还增加了颗粒层和光照效果，让整体氛围更接近参考游戏。

## 第 10 页：成果、验证与不足

- 完成两关可玩流程
- 完成寻路、旋转、条件连通和存档
- 完成 Windows 64 位打包
- 已验证编译、关卡加载和打包流程
- 不足：关卡数量少，动画、音效和编辑器仍需完善

备注讲稿：目前项目已经可以打包运行，核心玩法链路完整。但它仍然是原型，关卡内容、动作表现和音频都还有继续完善的空间。

## 第 11 页：总结与收获

- Python 阶段验证了投影和非欧连通思路
- Unity 阶段完成了可玩原型和构建流程
- 视觉错觉可以拆解为投影和连通条件
- AI 适合执行明确规格，不能替代设计与手感调整
- 后续重点是关卡拓展、测试地图和工具链完善

备注讲稿：这个项目让我把图形学原理、算法和 Unity 开发串了起来。最大的收获不是写出了多少代码，而是知道如何把“视觉错觉”这种抽象体验拆成可以计算、可以测试的系统规则。
